# Discord 互動劇情機器人

這是我在製作前一項RPG機器人的過程中，為了解決如何在聊天軟體上提供流暢劇情而開發的。最終做出了一個能讓創作者只需寫文字檔就能做出類日視覺小說的效果。

當初在開發RPG機器人劇情部分時，我發現長篇的文字往往會像洗版且不美觀，也不能清楚表示誰在說話，也沒有背景，非常麻煩。因此我在想：
**「能不能像寫小說一樣，在文字編輯器裡寫好劇本，機器人就自動幫我排版和處理存檔？」**

---

## 字句拆分

為了讓玩家有「看電影」般的節奏感，我設計了一套能字句拆分解析的邏輯。

### 1. 像小說一樣簡單的語法
我自創了一套標記法，讓不用懂程式也能控制劇情輸出：

**範例：**
```text
[scene1]
<forest_bg>
皮諾丘:這就是森林嗎？{好奇}
提問:要往哪裡走？
選擇1:走向深處 -> [scene2]
選擇2:留在原地 -> [scene3]
```

### 2. 字句拆分
*   **句子呈現**：我的程式會將劇本內容讀入後，拆出是

  - 故事章節(scene1)
  - 背景圖片(forest_bg)
  - 誰在說話(皮諾丘)
  - 什麼心情(好奇)

*   **按鈕互動**：用Discord的 `Button` 組件製作「下一句」功能。每點一次，程式就會從列表裡取出下一行對話，並動態更新嵌入訊息。
*   **視覺聯動**：程式會自動把 `{好奇}` 這種標記轉換為資料庫裡的圖片網址，隨時更換角色圖片。

## 後台資料整合

### 1. TXT 劇本與 SQL
不想把圖片網址寫死在程式碼裡，所以應用了前機器人學到的 SQLite 資料庫來管理資源。

*   **自動化檢索**：當拆到 `皮諾丘{難過}`這句，它會去資料庫執行：
    `SELECT url FROM character_images WHERE name='皮諾丘' AND emotion='難過'`
*   **優點**：如果我想換角色的畫風，我只需要去資料庫改網址，完全不用動到劇本或程式。

### 2. 閱讀存檔
我再利用 SQL 建立了 `progress.db`，記錄每個人的 Discord ID 對應到的劇情進度。這樣下次回來就能選擇繼續遊戲，從上次斷掉的地方開始。
